# LabFlow

LabFlow 是一个局域网实验室批次协同工具，用于管理化学合成与生物测试进度。

## 启动

宿主是 Linux 服务器，由 systemd 托管，开机自启。常用命令：

```bash
sudo pixi run service-install   # 首次部署 / 更新：安装服务并开机自启
systemctl status labflow        # 查看状态
sudo systemctl restart labflow  # 重启
```

调试时可前台运行：

```bash
pixi run serve
```

首次部署、备份、回滚的完整步骤见：

[docs/运维手册.md](docs/运维手册.md)

## 访问地址

服务监听 `0.0.0.0:9002`，端口在 `deploy/labflow.env` 中配置。

```text
服务器本机：http://127.0.0.1:9002
局域网其他电脑：http://服务器电脑IP:9002
```

查服务器 IP：

```bash
hostname -I
```

取第一个地址即可，形如 `192.168.x.x`。换网络后 IP 会变，用 `hostname -I` 重新看一下，
把新地址发给同事。如果其他电脑打不开，检查服务器防火墙是否放行了 TCP `9002`：

```bash
sudo ufw allow 9002/tcp        # 使用 ufw 的发行版
sudo firewall-cmd --add-port=9002/tcp --permanent && sudo firewall-cmd --reload   # 使用 firewalld 的发行版
```

## 默认账号

首次启动会自动创建这些账号。登录后请尽快修改密码。

| 角色 | 账号 | 默认密码 |
| --- | --- | --- |
| 总负责人 | leader | labflow123 |
| 化学部门 | chem1 / chem2 / chem3 | chem123 |
| 生物部门 | bio1 / bio2 / bio3 / bio4 / bio5 | bio123 |

总负责人可在页面右上角“账号”里重置其他账号密码。

## 权限

- 总负责人：创建/删除项目和批次，编辑全部字段，上传全部文件。
- 化学部门：创建批次，编辑批次编号、批次名称、合成提交时间、合成完成时间，上传化合物信息文件。
- 生物部门：编辑生物测试开始时间、生物测试完成时间，上传生物原始数据文件和数据整理文档。
- 所有账号都可以查看全部项目、批次、状态和文件历史版本。

## 文件格式

- 化合物信息文件：支持 Excel、CSV、PDF、Word，可一次上传多个文件。
- 生物原始数据文件：支持 Excel、CSV。
- 试验记录：支持 Excel、CSV、PDF、Word，可一次上传多个文件；Leader、Chem、Bio 均可上传/下载。
- 数据整理文档：支持 Excel、CSV、PDF、Word，可一次上传多个文件。
- 实验小结：支持 Excel、CSV、PDF、Word，可一次上传多个文件；Leader、Chem、Bio 均可上传/下载。
- 文件不会覆盖旧文件，所有历史文件都可在“全部”中逐个下载。

## 数据位置

- 数据库（seekdb）：`data/seekdb/`
- 数据库（sqlite 回滚点）：`data/labflow.db`
- 上传文件：`uploads/`
- 备份产物：`backups/`

备份用 `pixi run backup`，不要只靠手抄文件夹。见 [docs/运维手册.md](docs/运维手册.md)。

## 删除与恢复

项目和批次删除后会进入回收站，不会立即物理删除。总负责人可在页面右上角“回收站”中恢复。

恢复规则：

- 如果项目被删除，需要先恢复项目。
- 项目恢复后，才能恢复该项目下的批次。
- 批次名称必须全系统唯一，包括回收站中的批次。

## 批次唯一性

- 批次编号可以重复。
- 批次名称不能为空，且必须全系统唯一。

## 防火墙

如果其他电脑打不开页面，确认服务器防火墙放行了 TCP `9002`（见上方“访问地址”）。

## 状态规则

- 没有合成提交时间：待合成
- 有合成提交时间，没有合成完成时间：合成中
- 有合成完成时间，没有生物测试开始时间：待测试
- 有生物测试开始时间，没有生物测试完成时间：测试中
- 有生物测试完成时间：已完成
