### 已知项（非本次回归、不阻塞切换）

**停服/重启时 stderr 出现连接 reset traceback。** seekdb 后端退出时打印
`pymysql.err.OperationalError: (2006, "MySQL server has gone away")`，sqlite 后端
打出 `Exception closing connection` + `Exception ignored in atexit callback _shutdown`。
根因是 `server/handler.py` 的 `list_trash` 在 `with db_session()` 之外调用
`serialize_deleted_batch`，借出的连接要等 GC 才还池，进程退出时池再去 reset 这条
已失效连接。**只影响停服时的 stderr 噪音，不产生对外 5xx、不影响数据**，两套后端
都存在，已单独开单 **VYB-402**。修复前，把这类 traceback 视为预期现象，按次数计数即可。

- **窗口结束（2026-10-21）后的处置**：若期间观察指标无异常，冻结的 sqlite 回滚点
  转为普通归档（保留但不再作为回滚手段）；若期间触发回滚条件，则按第 2 节流程回退，
  并把差异补进本记录。

### 回滚触发条件（满足任意一条即回退）

1. 迁移后行数或校验和与冻结点不一致；
2. 出现无法在 30 分钟内定位并修复的对外 5xx；
3. seekdb 崩溃/残留子进程导致服务不可用，且重启无法恢复；
4. 关键流程（上传、下载、删除、恢复、回收站）出现失败或数据不一致。
